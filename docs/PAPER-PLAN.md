# Paper plan: metadata filling for the Zambia National ETD Portal

**Status:** agreed with Lighton Phiri on November 1, 2026. **This is the final step of the project:** when the portal build is complete, the last session drafts the paper from this plan and the evidence logged below. Every hand-off note must carry this plan forward (section "Final step: the paper").

## Working framing
*Calibrated, evidence-grounded metadata extraction, distilled for a resource-constrained national ETD aggregator.* The contribution is not only the models but showing that a national aggregator in the Global South can fill missing ETD-MS metadata to a guaranteed precision with no paid APIs, no owned GPU and a 3.8 GB shared server.

Earlier DataLab work (Phiri 2020; Chipangila et al. 2021, 2023; Kasonde, Chisale and Phiri 2022–2024; Nyambe et al., in revision, preprint to be posted on arXiv) is background and related work, not the method.

## Method (as built, in order)
1. Rules baseline `titlepage-rules` (in production since November 1, 2026).
2. Gold standard: stratified sample (`netd.cli gold-sample`), annotated, with inter-annotator agreement; admin corrections as further labels.
3. Layout-aware parsing (e.g. Docling/Marker) and page-type classification of preliminary pages; vision-language OCR for scanned PDFs.
4. One schema-constrained, evidence-grounded LLM extraction pass (open-weight 7–14B, quantised); values without a verbatim evidence span are discarded.
5. Calibration (isotonic on gold; self-consistency, token probabilities, rules agreement) and thresholds chosen for target precision from risk–coverage curves.
6. Distillation into a small CPU model that runs nightly on the server.
7. Normalisation to authority lists: supervisors (name variants, ORCID), HEI units, HEA-accredited programmes, ISCED-F 2013 fields.
8. Standard fields of study for every record from OpenAlex Topics (FR-54 to FR-57; built November 1, 2026): embeddings + linear classifier trained on OpenAlex-labelled works, hierarchical back-off; next: tune thresholds, add repository keywords as input, annotate portal records, compare with fine-tuned encoders; embeddings reused for duplicates (FR-19) and search.
9. Active learning from corrections and the review list.

## Compute (no owned GPU, no paid APIs)
- **GPU work is a one-off backfill plus occasional retraining, never part of the nightly pipeline.** It runs on free notebook GPUs (Kaggle: about 30 GPU-hours a week, 12-hour sessions, background execution; Google Colab free tier as a second option), in resumable chunks that checkpoint to files, and comes back as JSON Lines through `netd.cli load-predictions`.
- **Nightly work is CPU-only on the server:** text extraction, Tesseract for any new scans, the rules model and the distilled model.
- **Fallback with no GPU at all:** a quantised small LLM via llama.cpp on a laptop CPU overnight (days, not hours, for the backfill); or train the student only on the gold standard and corrections.

## Technical record from session 03 (November 1, 2026), for writing the paper

### System context
- Portal: Python harvester (OAI-PMH, DSpace REST fallback, CSV loader) → SQLite staging store (raw XML kept untouched; canonical ETD-MS-style records with per-field provenance and confidence) → Apache Solr 9.11 → Project Blacklight 9 on Rails 8 (UI modelled on Columbia's Academic Commons); own OAI-PMH provider (oai_dc, ETD-MS) and REST API; admin panel. One shared Ubuntu 20.04 server (2 vCPU, 3.8 GB RAM) hosted by ZAMREN; no GPU, no paid services.
- Collection on November 1, 2026: 5,923 postgraduate ETDs (UNZA 5,733, ZCAS 116, UNILUS 62, Mulungushi 12); 34 HEA-listed institutions, 30 with no harvestable ETDs.
- Architecture, pipeline, metadata-filling and field-of-study diagrams (reusable as paper figures): `blog-datalab26-netd_portal_implementation.zip` (SVG sources), generated by a script kept with it.

### Design decisions and rationale (metadata filling)
- **Models never write records.** Predictions go to a cache (record, field, model, version, value, confidence, evidence text, input hash); models rerun only when their input hash (PDF text hash + harvested values used + model version) changes. Models see harvested values only, never other models' output (no feedback loops).
- **Precedence:** manual correction > harvested value > prediction. A prediction fills only an empty field, only at confidence ≥ 0.8 (per-field override possible), and is marked "derived" (record page badge with model and confidence; API `derived` object).
- **Asymmetric risk for exclusion:** a predicted below-postgraduate degree level removes a record, so it is applied only at ≥ 0.95; 0.6–0.95 goes to a human review list; decisions are stored as corrections.
- **Front matter first:** some repositories split a thesis into "Cover page", "Preliminary pages" and "Main Document" files, and the first file is often the main document starting at Chapter 1; reading cover/preliminary files first was essential for UNZA.
- **Text:** first 8 pages per file (pypdf); scans (text layer < 80 characters) OCRed with Tesseract (first 5 pages, 200 dpi, greyscale, lowest CPU priority, about 18 s per PDF on the shared server).
- **Guarded application:** predict → dry run on a copy of the store → apply only if model-driven exclusions stay within a limit (10) (`deploy/ops/netd-ml-apply.sh`).

### Data observations
- UNZA: about 25% of PDFs are scans (1,455 of ~5,700), mostly pre-2015; about 7.5% of PDF links returned HTTP 500 from the repository at extraction time (431); 14 PDFs exceeded 60 MB. UNILUS links, internal-only earlier, mostly worked (51 of 62).
- PDF text extraction artefacts that rules must handle: words split by spaces ("M aster", "Zambi a", "Eco nomics"), hyphenated surnames with a stray space ("Chama -Chiliba"), names in all capitals, several supervisors on one line joined by commas, "and" or titles, and lines running into the next one (thesis title after a department name; "Word Count" or a copyright notice after a name or degree).
- Supervisor evidence locations seen: "Supervisor:" lines on approval/declaration pages, "supervised by", "under the supervision of", and acknowledgements ("my supervisor(s), Dr X and Prof Y"; "Dr X, my supervisor") — consistent with Nyambe et al. (in revision).

### Rules model development (`titlepage-rules`, versions 1–9, all November 1, 2026)

## Technical record from session 05 (November 2, 2026), for writing the paper

### Operating a national service on a shared, under-resourced server
- NETD shares one 2-vCPU VM with seven other services owned by other projects; there is no snapshot or console access on our side, so the only way back is our own backup. The backup went to the project's Google Drive (UNZA account) with rclone; on this link Drive uploads needed 128 MB chunks (13 MB/s) instead of the 8 MB default (0.3 MB/s): a 45-fold difference that decides whether an off-site copy of 10 GiB takes 10 minutes or 9 hours.

Each is now a step in the checklist. Lesson for the paper: in shared hosting, an aggregator's availability depends as much on operations discipline as on its own code.
- The upgrade also showed the cost of the repository outage to the evaluation timeline: the OCR backlog, and with it the final evaluation, waited over 16 hours on one institution's network.

## Technical record from session 07 (November 2, 2026), for writing the paper

### Usage analytics without tracking
- Design choice: count inside the application, not from web-server logs and not with a third-party script. The Apache log on this server is shared with the other web services on it (OJS, ZNRP, the EMI site) and holds IP addresses; a hosted tracker would send readers' data abroad and needs a cookie notice under Zambia's Data Protection Act (2021). The portal keeps one row per (UTC day, event, record, institution) with a count, and nothing that identifies a reader.
- PDF downloads are only visible if the reader goes through the portal: Download links now point to `/catalog/<id>/pdf`, which counts and redirects (302) to the link stored in the record (no open redirect). Downloads started from the repository's own pages, or by crawlers, are not counted; the figure is a lower bound on use of the full texts.
- Crawler filtering is by user-agent pattern; a crawler that pretends to be a browser is counted. API and OAI-PMH requests are counted without filtering, since their users are programs. For the paper: report views and downloads per institution over a stated period, with these caveats.
- Finding: Blacklight's default search history kept every search (query and facets) of every visitor, crawlers included; 540,539 rows in three days. Now pruned to one day nightly. Lesson: an off-the-shelf discovery layer can keep more about its users than its operators know.

### Name variants of academic units
- Department names reach the portal from three places (collection names, description text, the title-page model), and each repeats the repository's inconsistencies: singular/plural, "&", word order, hyphen spacing, typos on title pages. A deterministic key (case, word order, plural endings and stop words ignored) merged most variants; an edit-distance rule limited to rare values (≤ 2 records) joining much larger groups (≥ 3×) caught typos without merging real distinctions ("Mathematics" vs "Mathematics and Statistics", "Electrical" vs "Electrical and Electronic Engineering" left apart: key similarity below 0.92).
- Applied at index time only, so the evaluated predictions and gold comparison are unchanged; the original spelling stays in Solr. Not solved: different units that share a name across faculties, and wrong faculty–department pairs from the model.
- Collection names are not always academic units (a journal title, "Ministry of Health"; "Library" is a real unit at UNZA, outside the Schools); a per-source mapping (`set_units`) fixes them by configuration, and one collection held a non-thesis (a national plan).

### Error analysis of supervisor misses, and a measurement bug

## Technical record from session 10 (November 2, 2026), for writing the paper

### Supervisor name variants (FR-64)
- One person's name reaches the portal in many spellings: from the repository record ("Prof. A. M. Cheyeka"), from the title page through the model ("Austin Mumba Cheyeka"), with or without titles, initials run together ("JM Mandyata"), surname first ("Dr Phiri J"), capitals ("ROBert TEMBO"), split or joined words ("ChristineW Kanyengo"). At UNZA, 1,950 supervisor spellings stood for about 1,300 people. This splits facet counts, Browse and the per-supervisor reports for HEA.
- Design: a display-time step, like department names (FR-62): per institution, at indexing; the staging store and the predictions are not changed, so evaluated figures cannot move. Names are parsed with the evaluator's own parser (`person_words`, split out of `_person` without changing its behaviour), so "the same person" means the same thing in the evaluation and in the portal.
- Precision over recall, because a wrong merge credits one person's theses to another: spellings are grouped from the most specific to the least; a spelling joins only a group whose every member agrees with it, and only when that group is the sole candidate of that surname or the sole one sharing a department (then faculty). **Bare surnames are never joined**: the gold standard showed that one bare spelling ("Mweemba") stands for different people across records (L. Mweemba on the title page; the only full-named Mweemba in the portal was Oliver Mweemba), and a per-spelling mapping cannot split it. Common surnames are handled by the same rule: "J. Phiri" stays apart when both Jackson and John Phiri exist, unless the department decides.
- The shown spelling is the fullest one in ordinary capitals (more given names first), not the most frequent: a shorter shown form loses initials that a reader (and a matcher) can use. With the most frequent form shown, one test record lost a gold match through the evaluator's mapping check; with the fullest form, none did.
- Readers still see what the source said: the record page shows "As written in the record", and a search for the original spelling still finds the thesis.

### Usage analytics: separating readers from robots and from ourselves
- The first day's counts (November 2) were mostly the project's own testing, and a US "reader" was an uptime monitor. ## Technical record from session 15 (November 5, 2026, maintenance track; post-paper)

### Depending on a free external service (FR-69)
- OpenAlex refuses keyless search not only when the day's $0.10 is spent but also when its search cluster is busy (HTTP 429 with `Retry-After`). The job treated every 429 as "allowance used up" and stopped for the night, so the first nightly run checked nothing, and its log line wrongly blamed the budget. The client now tells the two apart (waits as asked, up to five minutes a run) and says which one stopped it; a rejected API key no longer stops the job.
- Decision (Lighton): use his own free OpenAlex key until the HEA handover, then HEA's; the swap is one line on the server and changes no data. For the paper's "resource-constrained deployment" discussion: a free, keyless allowance is a fragile basis for a national service; a free key, owned by the operating institution, is the cheap fix.
